# 고도 노이즈 보정 설계

날짜: 2026-08-20

## 문제

러닝 기록 상세 화면의 고도 그래프가 평지 코스에서도 심하게 요동친다.
실측 예: 하남 미사동 한강변 직선 코스 2.02km(고도 변화 사실상 없음)에서
그래프는 산악 코스처럼 진동하고 총 상승고도가 `↑15 m`로 표시됐다.

원인은 세 가지이며 서로 독립적이다.

1. **스무딩 부족** — `smoothAltitudes`(`src/lib/splits.ts`)의 이동평균 윈도우가
   포인트 5개(`SMOOTH_WINDOW_HALF = 2`)뿐이다. 로깅 간격이 3초/5m이므로
   실효 윈도우가 약 15~25초에 불과해 GPS 고도 노이즈(±5~10m, 수십 초 상관)를
   흡수하지 못한다. 또한 포인트 개수 기준이라 러너 속도에 따라 실효 강도가 달라진다.
2. **y축 자동 스케일** — `ElevationChart`(native/web 양쪽)이 y 도메인을 데이터
   min/max에 맞춘다. 평지에서 잔여 노이즈가 ±2m만 남아도 그래프가 차트 높이를
   가득 채워 큰 기복처럼 보인다. 체감상 이것이 주된 원인이다.
3. **상승고도 과대 합산** — `elevationGainM`이 스무딩 후 양(+)의 변화를 전부
   합산한다. 노이즈의 상승 성분이 그대로 누적되어 평지에서도 십수 미터가 나온다.

기록 시 `verticalAccuracy`를 저장하지 않으므로 이미 저장된 기록에는 정확도 기반
이상치 판별 근거가 없다. 따라서 보정은 **저장된 고도 시계열만으로 계산 시점에**
수행해야 하고, 그 대가로 기존 기록에도 소급 적용된다.

## 범위

- 고도 그래프 표시 보정
- 총 상승고도 수치 보정
- 구간(스플릿)별 고도차 안정화 — 강화된 스무딩의 부수 효과

범위 밖:

- 기록 시 `verticalAccuracy` 저장 및 이상치 제거 (신규 기록만 개선되므로 별건)
- 기압계(barometer) 활용, DEM/고도 API 보정
- 저장된 `RunRecord` 스키마 변경, 마이그레이션, 백필

## 접근 방식

거리 기반 다단 필터 + 차트 y축 최소 표시범위. 순수 함수로 구현해 기존 기록에도
소급 적용되고 단위 테스트가 쉽다.

검토했으나 채택하지 않은 대안:

- **EMA/칼만 필터** — 구현은 짧지만 단방향 적용 시 위상 지연이 생겨 그래프의
  언덕이 실제 위치보다 뒤로 밀린다. 양방향으로 보정하면 결국 아래 설계와
  비슷한 복잡도가 되므로 이점이 없다.
- **`verticalAccuracy` 기반 이상치 제거** — 신규 기록만 개선된다. 문제를 제기한
  기록 자체는 그대로 남는다.

## 설계 1 — 고도 필터 모듈

`src/lib/elevation.ts`를 새로 만들고 고도 관련 함수를 `src/lib/splits.ts`에서
옮긴다. `splits.ts`는 이미 230줄이고 구간 계산과 고도 계산이 섞여 있다.

이동 대상: `smoothAltitudes`, `elevationGainM`, `elevationProfile`,
`formatElevationDelta`, `ProfilePoint`. `computeSplits`는 `elevation.ts`에서
`smoothAltitudes`를 import한다(단방향, 순환 없음).

`splits.ts`에 재export를 남기지 않는다. 옮긴 심볼을 쓰는 모든 호출부의 import
경로를 `@/lib/elevation`으로 갱신한다(`src/components/SplitsList.tsx`,
`src/components/ElevationChart.tsx`, `src/components/ElevationChart.web.tsx`,
`app/run/[id].tsx`, 관련 테스트). 이동 후 `grep`으로 잔여 참조가 없는지 확인한다.

`smoothAltitudes(points: RoutePoint[]): (number | null)[]` 내부를 2단계로 바꾼다.

**1단계 — 중앙값 필터(윈도우 5, 중심 ±2)**
단발성 스파이크를 제거한다. 윈도우 내 `null`이 아닌 값들의 중앙값을 취하고,
값이 없으면 `null`. 짝수 개면 가운데 두 값의 평균.

**2단계 — 거리 기준 이동평균(±50m)**
각 포인트의 누적 거리를 `haversineM`으로 계산하고, 누적 거리가 해당 포인트
±50m 이내인 이웃들의 1단계 결과 평균을 취한다. 거리 기준이므로 러너 속도와
무관하게 실효 강도가 일정하다. 누적 거리는 단조 증가하므로 two-pointer로
윈도우를 밀면서 부분합을 갱신해 전체 O(n)으로 계산한다.

`null` 처리 규칙은 현재 동작을 유지한다. 입력 고도가 `null`인 포인트의 출력은
`null`이고, 이웃의 평균 계산에서도 제외된다.

일시정지 구간 경계는 특별 취급하지 않는다. 입력은 지금처럼 flat 배열이고,
일시정지 중 이동한 거리는 누적 거리에 포함되어 윈도우가 그만큼 넓어진다.
평탄화 방향으로만 작용하므로 허용한다.

상수는 모듈 상단에 명명 상수로 둔다: `MEDIAN_WINDOW_HALF = 2`,
`SMOOTH_RADIUS_M = 50`.

**윈도우 반경을 50m로 유지하는 근거.** 프로토타입 파라미터 스윕(반경 50/100/150/250m
× 임계값 3/5/8/10m)에서 반경 확대는 손실만 컸다. GPS 고도 노이즈는 고주파 지터가
아니라 수백 미터~km 주기의 저주파 드리프트라서, 100~250m 윈도우로도 제거되지
않는다(평지 2km 드리프트 진폭이 8.6m → 6.4 → 5.6 → 3.6m로 완만하게만 줄어든다).
반면 실제 지형은 빠르게 뭉개진다. 진폭 10m·주기 400m 롤링힐 4km 코스의 총 상승고도는
반경 50m에서 152.6m지만 반경 150m 이상에서는 0m가 된다. 343m에 50m 오르는 급경사도
반경 50m에서 41.5m, 250m에서 10.1m로 무너진다. 즉 윈도우 확대는 드리프트에 무력한데
실제 언덕만 죽이는 방향이다. 드리프트는 아래 설계 2의 임계값으로 처리한다.

## 설계 2 — 총 상승고도 히스테리시스

`elevationGainM`의 합산 규칙을 임계값 5m 히스테리시스로 바꾼다. 입력 `alts`는
현재와 동일하게 `smoothAltitudes` 결과에서 `null`을 제거한 배열이다.

```
ref = alts[0]
gain = 0
for a in alts[1:]:
  if a - ref > 5:   gain += a - ref;  ref = a
  elif ref - a > 5: ref = a
```

기준점 `ref`에서 3m 이상 올라갔을 때만 그 상승분을 인정하고 기준점을 옮긴다.
3m 이상 내려가면 상승분 없이 기준점만 옮긴다. 평지 잔여 노이즈는 임계값을
넘지 못해 `gain`이 0에 가깝게 유지되고, 완만한 실제 언덕은 상승분이 계속
누적되므로 총량이 보존된다.

유효 고도가 2개 미만이면 `null` — 현재 동작 유지.
임계값은 명명 상수 `GAIN_THRESHOLD_M = 5`.

**임계값을 5m로 두는 근거.** 드리프트를 죽이려면 임계값이 드리프트 진폭(스무딩 후
약 ±4m)을 넘어야 한다. 스윕에서 평지 2km + 드리프트 노이즈의 총 상승고도는 임계값
3m에서 15.2m — 문제를 제기한 기록의 `↑15 m`와 사실상 동일한 값이라 3m로는 증상이
그대로 남는다. 5m에서 0.0m로 떨어진다. 5m는 실제 지형 보존 면에서도 3m보다 낫다.
2km에 50m 상승은 45.8m(3m일 때 47.2m), 롤링힐 4km는 152.6m(3m일 때 131.9m)로,
임계값이 낮으면 기준점이 자주 리셋되어 오히려 손실이 커지는 구간이 있다.

**남는 한계.** 완만한 실제 상승은 약 8% 과소 계상된다(2km에 50m → 45.8m). 그중
대부분은 히스테리시스가 아니라 중심 이동평균의 양 끝 감쇠에서 온다(양 끝 스무딩
고도가 0.65m / 49.35m). 롤링힐은 약 25% 과소 계상된다(200m → 152.6m). 기압계나
DEM 고도 API 없이 고도 시계열만으로는 저주파 드리프트와 완만한 실제 언덕을
원리적으로 구분할 수 없으므로, 이 과소 계상은 과대 계상을 없애기 위해 받아들이는
대가다. 과대보다 과소가 낫다고 판단한 근거는 사용자가 제기한 문제가 과대이기 때문이다.

## 설계 3 — 차트 y축 최소 표시범위

`elevation.ts`에 공용 헬퍼를 추가한다.

```ts
export function elevationYDomain(
  profile: ProfilePoint[],
  minSpanM = 40
): [number, number]
```

프로필의 고도 min/max를 구해 범위가 `minSpanM` 미만이면 중앙값
`(min + max) / 2`을 중심으로 `minSpanM` 폭으로 확장해 반환한다. 그 이상이면
실제 min/max를 그대로 반환한다. 평지는 거의 평평한 선으로, 실제 언덕은 지금처럼
전체 높이를 쓰는 그래프로 보인다.

**최소 표시범위를 40m로 두는 근거.** 스무딩은 드리프트를 지우지 못하므로 평지
2km에서도 잔여 진폭 약 8.6m가 그래프에 남는다. 최소범위 20m면 이 8.6m가 차트
높이의 43%를 차지해 여전히 뚜렷한 기복으로 보인다. 40m면 21%로 완만한 물결이 된다.
실제 지형은 손실이 없다. 범위 40m 이상인 코스는 실제 min/max를 그대로 쓰고,
그보다 작은 언덕도 비율만 줄어든 채 그대로 보인다.

빈 프로필/포인트 1개는 차트가 렌더하지 않으므로(`profile.length < 2` 가드)
호출되지 않지만, 헬퍼 자체는 빈 배열에 `[0, minSpanM]`을 반환해 방어한다.

**native** (`src/components/ElevationChart.tsx`) — `CartesianChart`에
`domain={{ y: elevationYDomain(profile) }}` 전달.

**web** (`src/components/ElevationChart.web.tsx`) — 기존 `minA`/`range` 지역
계산을 헬퍼 결과로 교체한다. 두 차트가 같은 도메인 규칙을 쓰게 하는 것이
이 헬퍼를 공용으로 두는 이유다.

## 테스트

`src/lib/__tests__/elevation.test.ts`를 신규 작성한다. 구현 전에 테스트를 먼저
작성한다.

`smoothAltitudes`:

- 평지(고도 100m 고정) + ±5m 톱니 노이즈 200포인트, 7m 간격 →
  출력의 min/max 폭 3m 미만 (실측 2.222m)
- 단발 스파이크(+30m 1포인트) → 해당 지점 출력이 스파이크 없는 이웃과 동일
  (실측 정확히 100)
- 단조 상승(2km에 50m) → 양 끝 출력이 실제 값과 1m 이내
  (실측 0.647 / 49.353 — 양 끝 감쇠는 있지만 언덕을 뭉개지 않음)
- `null` 고도 포인트 → 출력 `null`, 이웃 평균에서 제외 (기존 회귀)
- 전부 `null` → 전부 `null`

`elevationGainM`:

- 평지 + 저주파 드리프트 노이즈 2km → 정확히 0 (실측 0.0)
- 평지 + ±5m 톱니 노이즈 → 정확히 0
- 2km에 50m 단조 상승 → 45~50m (실측 45.844)
- 상승 후 같은 높이로 하강 → 상승분만 계상 (하강분 미합산)
- 유효 고도 0~1개 → `null`

`elevationYDomain`:

- 평지 프로필(범위 1m, 중앙값 100) → `[80, 120]`
- 언덕 프로필(고도 20~100, 범위 80m) → `[20, 100]` (실제 min/max 그대로)
- 빈 배열 → `[0, 40]`

`computeSplits` 관련:

- 기존 `src/lib/__tests__/splits.test.ts`의 `computeSplits` 고도 케이스는 기대값이
  바뀌지 않는다. 해당 테스트는 위도 0.001도(약 111m) 간격이라 ±50m 이동평균이
  자기 자신만 포함해 사실상 무연산이 되고, 데이터가 선형이라 중앙값과 평균이 같기
  때문이다(스무딩 결과 `[0]=2`, `[19]=36` — 기존과 동일).

세 개의 기존 테스트는 갱신이 필요하다. 갱신 사유를 테스트 주석에 남긴다.

1. `smoothAltitudes` 윈도우 테스트 — 현재 포인트를 `latitude: 0` 고정으로 만들어
   모든 포인트의 누적 거리가 0이다. 거리 기준 윈도우에서는 전부 서로의 이웃이 되어
   출력이 `[30, 30, 30, 30, 30]`으로 뭉개진다. 파일의 다른 테스트처럼 위도를
   0.001도씩 벌리면 출력이 `[20, 25, 30, 35, 40]`이 되어 기존 단정이 그대로
   통과한다. 이 테스트는 `elevation.test.ts`로 옮기면서 함께 수정한다.
2. `elevationGainM` 단조 증가 테스트 — 히스테리시스 도입으로 기대값이 14에서
   12로 바뀐다(임계값 미달분이 계상되지 않음).
3. `elevationGainM` 다중 그룹 테스트 — 현재 데이터의 총 상승이 4m라 임계값 5m를
   못 넘어 결과가 0이 되고, "그룹을 이어서 합산한다"는 검증 의도가 사라진다.
   고도 간격을 2m에서 10m로 키워(`flat = [0, 10, 20, 20, 30, 40]`) 기대값 20으로
   교체한다.
