# 고도 노이즈 보정 설계

날짜: 2026-08-20

## 문제

러닝 기록 상세 화면의 고도 그래프가 평지 코스에서도 심하게 요동친다.
실측 예: 하남 미사동 한강변 직선 코스 2.02km(고도 변화 사실상 없음)에서
그래프는 산악 코스처럼 진동하고 총 상승고도가 `↑15 m`로 표시됐다.

원인은 세 가지이며 서로 독립적이다.

1. **스무딩 부족** — `smoothAltitudes`(`src/lib/splits.ts`)의 이동평균 윈도우가
   포인트 5개(`SMOOTH_WINDOW_HALF = 2`)뿐이다. 로깅 간격이 3초/5m이므로
   실효 윈도우가 약 15~25초에 불과해 GPS 고도 노이즈(±5~10m, 수십 초 상관)를
   흡수하지 못한다. 또한 포인트 개수 기준이라 러너 속도에 따라 실효 강도가 달라진다.
2. **y축 자동 스케일** — `ElevationChart`(native/web 양쪽)이 y 도메인을 데이터
   min/max에 맞춘다. 평지에서 잔여 노이즈가 ±2m만 남아도 그래프가 차트 높이를
   가득 채워 큰 기복처럼 보인다. 체감상 이것이 주된 원인이다.
3. **상승고도 과대 합산** — `elevationGainM`이 스무딩 후 양(+)의 변화를 전부
   합산한다. 노이즈의 상승 성분이 그대로 누적되어 평지에서도 십수 미터가 나온다.

기록 시 `verticalAccuracy`를 저장하지 않으므로 이미 저장된 기록에는 정확도 기반
이상치 판별 근거가 없다. 따라서 보정은 **저장된 고도 시계열만으로 계산 시점에**
수행해야 하고, 그 대가로 기존 기록에도 소급 적용된다.

## 범위

- 고도 그래프 표시 보정
- 총 상승고도 수치 보정
- 구간(스플릿)별 고도차 안정화 — 강화된 스무딩의 부수 효과

범위 밖:

- 기록 시 `verticalAccuracy` 저장 및 이상치 제거 (신규 기록만 개선되므로 별건)
- 기압계(barometer) 활용, DEM/고도 API 보정
- 저장된 `RunRecord` 스키마 변경, 마이그레이션, 백필

## 접근 방식

거리 기반 다단 필터 + 차트 y축 최소 표시범위. 순수 함수로 구현해 기존 기록에도
소급 적용되고 단위 테스트가 쉽다.

검토했으나 채택하지 않은 대안:

- **EMA/칼만 필터** — 구현은 짧지만 단방향 적용 시 위상 지연이 생겨 그래프의
  언덕이 실제 위치보다 뒤로 밀린다. 양방향으로 보정하면 결국 아래 설계와
  비슷한 복잡도가 되므로 이점이 없다.
- **`verticalAccuracy` 기반 이상치 제거** — 신규 기록만 개선된다. 문제를 제기한
  기록 자체는 그대로 남는다.

## 설계 1 — 고도 필터 모듈

`src/lib/elevation.ts`를 새로 만들고 고도 관련 함수를 `src/lib/splits.ts`에서
옮긴다. `splits.ts`는 이미 230줄이고 구간 계산과 고도 계산이 섞여 있다.

이동 대상: `smoothAltitudes`, `elevationGainM`, `elevationProfile`,
`formatElevationDelta`, `ProfilePoint`. `computeSplits`는 `elevation.ts`에서
`smoothAltitudes`를 import한다(단방향, 순환 없음).

`smoothAltitudes(points: RoutePoint[]): (number | null)[]` 내부를 2단계로 바꾼다.

**1단계 — 중앙값 필터(윈도우 5, 중심 ±2)**
단발성 스파이크를 제거한다. 윈도우 내 `null`이 아닌 값들의 중앙값을 취하고,
값이 없으면 `null`. 짝수 개면 가운데 두 값의 평균.

**2단계 — 거리 기준 이동평균(±50m)**
각 포인트의 누적 거리를 `haversineM`으로 계산하고, 누적 거리가 해당 포인트
±50m 이내인 이웃들의 1단계 결과 평균을 취한다. 거리 기준이므로 러너 속도와
무관하게 실효 강도가 일정하다. 누적 거리는 단조 증가하므로 two-pointer로
윈도우를 밀면서 부분합을 갱신해 전체 O(n)으로 계산한다.

`null` 처리 규칙은 현재 동작을 유지한다. 입력 고도가 `null`인 포인트의 출력은
`null`이고, 이웃의 평균 계산에서도 제외된다.

일시정지 구간 경계는 특별 취급하지 않는다. 입력은 지금처럼 flat 배열이고,
일시정지 중 이동한 거리는 누적 거리에 포함되어 윈도우가 그만큼 넓어진다.
평탄화 방향으로만 작용하므로 허용한다.

상수는 모듈 상단에 명명 상수로 둔다: `MEDIAN_WINDOW_HALF = 2`,
`SMOOTH_RADIUS_M = 50`.

## 설계 2 — 총 상승고도 히스테리시스

`elevationGainM`의 합산 규칙을 임계값 3m 히스테리시스로 바꾼다.

```
ref = alts[0]
gain = 0
for a in alts[1:]:
  if a - ref > 3:   gain += a - ref;  ref = a
  elif ref - a > 3: ref = a
```

기준점 `ref`에서 3m 이상 올라갔을 때만 그 상승분을 인정하고 기준점을 옮긴다.
3m 이상 내려가면 상승분 없이 기준점만 옮긴다. 평지 잔여 노이즈는 임계값을
넘지 못해 `gain`이 0에 가깝게 유지되고, 완만한 실제 언덕은 상승분이 계속
누적되므로 총량이 보존된다.

유효 고도가 2개 미만이면 `null` — 현재 동작 유지.
임계값은 명명 상수 `GAIN_THRESHOLD_M = 3`.

## 설계 3 — 차트 y축 최소 표시범위

`elevation.ts`에 공용 헬퍼를 추가한다.

```ts
export function elevationYDomain(
  profile: ProfilePoint[],
  minSpanM = 20
): [number, number]
```

프로필의 고도 min/max를 구해 범위가 `minSpanM` 미만이면 중앙값
`(min + max) / 2`을 중심으로 `minSpanM` 폭으로 확장해 반환한다. 그 이상이면
실제 min/max를 그대로 반환한다. 평지는 거의 평평한 선으로, 실제 언덕은 지금처럼
전체 높이를 쓰는 그래프로 보인다.

빈 프로필/포인트 1개는 차트가 렌더하지 않으므로(`profile.length < 2` 가드)
호출되지 않지만, 헬퍼 자체는 빈 배열에 `[0, minSpanM]`을 반환해 방어한다.

**native** (`src/components/ElevationChart.tsx`) — `CartesianChart`에
`domain={{ y: elevationYDomain(profile) }}` 전달.

**web** (`src/components/ElevationChart.web.tsx`) — 기존 `minA`/`range` 지역
계산을 헬퍼 결과로 교체한다. 두 차트가 같은 도메인 규칙을 쓰게 하는 것이
이 헬퍼를 공용으로 두는 이유다.

## 테스트

`src/lib/__tests__/elevation.test.ts`를 신규 작성한다. 구현 전에 테스트를 먼저
작성한다.

`smoothAltitudes`:

- 평지(고도 100m 고정) + 결정적 노이즈(±5m 톱니) 200포인트 →
  출력의 min/max 폭이 2m 미만
- 단발 스파이크(+30m 1포인트) → 해당 지점 출력이 이웃과 2m 이내
- 단조 상승(0→50m 선형) → 양 끝 출력이 실제 값과 5m 이내 (언덕을 뭉개지 않음)
- `null` 고도 포인트 → 출력 `null`, 이웃 평균에서 제외 (기존 회귀)
- 전부 `null` → 전부 `null`

`elevationGainM`:

- 평지 + 노이즈 → 2m 미만
- 단조 상승 50m → 45~50m
- 상승 50m 후 하강 50m → 45~50m (하강분 미합산)
- 유효 고도 0~1개 → `null`

`elevationYDomain`:

- 평지 프로필(범위 1m, 중앙값 100) → `[90, 110]`
- 언덕 프로필(범위 80m) → 실제 min/max
- 빈 배열 → `[0, 20]`

`computeSplits` 관련:

- 기존 `src/lib/__tests__/splits.test.ts`가 계속 통과해야 한다. 스무딩 강화로
  구간 고도차 기대값이 달라지는 케이스가 있으면 새 필터에 맞게 갱신하고,
  갱신 사유를 테스트 주석에 남긴다.
