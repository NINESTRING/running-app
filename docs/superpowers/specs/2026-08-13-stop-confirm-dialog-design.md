# 러닝 종료 확인 다이얼로그 설계

2026-08-13

## 목표

종료 버튼을 누르면 즉시 저장하지 않고, 기록을 저장할지·버릴지·계속할지 선택하는
확인 다이얼로그를 띄운다. 실수로 종료를 눌러도 러닝으로 복귀할 수 있어야 한다.

## 요구사항

- 종료 버튼 탭 시(러닝 중·일시정지 중 모두) 확인 다이얼로그 표시.
- 러닝 중이었다면 다이얼로그가 뜨는 순간 자동 일시정지 — 고민하는 시간이
  기록(시간·거리)에 포함되지 않는다.
- 선택지 3개:
  - **저장**: 기존 저장 흐름 그대로 실행.
  - **버리기**: 기록 폐기, idle 복귀. 별도 재확인 없음(이 다이얼로그가 확인 단계).
  - **취소**: 다이얼로그만 닫고 일시정지 유지. 재개 버튼으로 러닝 계속 가능.
    바깥 탭·뒤로가기 등으로 닫아도 취소와 동일.

## 구현

`app/(tabs)/index.tsx` 한 파일만 수정. 스토어 변경 없음.

- `DialogState`에 `{ type: 'confirmStop' }` 추가.
- 종료 버튼 `onPress`: 러닝 중이면 `pause(Date.now())` 호출 후
  `setDialog({ type: 'confirmStop' })`. 일시정지 중이면 다이얼로그만 연다.
- 다이얼로그 **저장** 버튼: 다이얼로그 닫고 기존 `onStop` 로직 실행
  (`beginSave` → 센서 중지 → 걸음 백필·날씨·위치 라벨 병렬 조회 → `saveRun`).
  `beginSave`는 paused 상태에서 진입하며, 기존 중복 저장 가드가 그대로 동작한다.
- 다이얼로그 **버리기** 버튼: `stopTracking()`(실패 무시)·`stopStepCounting()` 후
  `reset()`, 다이얼로그 닫음.
- 다이얼로그 **취소** / dismiss: `setDialog(null)`만. paused 상태 유지.

## 엣지 케이스

- 저장 실패: 기존과 동일 — `failSave()`로 paused 복귀 + "저장하지 못했습니다 /
  유지·버리기" 다이얼로그. 변경 없음.
- 종료 중복 탭: 첫 탭에서 paused 전환 + 다이얼로그가 열리므로 재진입 없음.
  저장 진행 중에는 버튼이 기존대로 "저장 중…" disabled.

## 테스트

새 순수 함수 없음(기존 스토어 액션 `pause`/`beginSave`/`reset` 재사용).
기존 테스트 통과 확인만 한다.
